### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `<plugin root>/skills/poteto-mode/scripts/worktree-audit.sh [-b <pr-base-ref>] [--fetch] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It writes nothing to the repository unless `--fetch` refreshes that base from origin first. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.claude/worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user, and from the T3 threads bound to each worktree (page through `t3_thread_list` with `includeSubagents: true` and read each thread's `worktreePath` with `t3_thread_read`), and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never show in the thread list. Pick each subagent's reasoning level and fast or standard speed for the job, per the Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is N untracked paths. Name them and get a decision, then delete only the ones the user approves with `git --literal-pathspecs -C <path> clean -fd -- <file>...`, so a name such as `notes[1].md` matches only itself. `ignored:N` is N ignored paths outside the build and cache directories the audit names, such as `.env` or `.claude/settings.local.json`, which may exist nowhere else. List them with the call the audit counts from, `git -C <path> status --porcelain --untracked-files=normal --ignored=matching`. `reflog:N` is N commits that no branch, tag, or remote reaches, kept only by the worktree's HEAD or its reflog, such as work committed on a detached HEAD. They are HEAD or among the entries `git -C <path> reflog` prints, and `git branch <name> <sha>` keeps one. `unknown` means git could not read the worktree, so treat it as `wip`. When `git worktree list` marks it `prunable`, its directory is gone, a plain remove does not refuse it, and removing it drops its HEAD and HEAD reflog. Its `<id>` is the directory under `.git/worktrees/` whose `gitdir` file names its path. From the main checkout, `git log -1 worktrees/<id>/HEAD` shows its HEAD and `git reflog show worktrees/<id>/HEAD` its reflog. Remove it per path in step 5, never with a bulk prune. Per Autonomy, clean and merged and not-in-use proceeds. `wip`, `unknown`, `scratch`, `ignored`, `reflog`, and in-use pause.
5. Prune the confirmed set. Per path, run a plain `git worktree remove <path>`. It deletes every ignored file with the directory, and under a `status.showUntrackedFiles=no` config every untracked file too, so a worktree with `scratch` or `ignored` waits for the user's decision from step 4. It refuses a worktree with tracked edits or a lock, and that refusal is the stop. Leave the worktree, report it, and never add a force flag or delete the directory by hand. Branch refs survive, so commits on the worktree's branch are kept. The worktree's HEAD reflog goes with it, which is why step 4 holds `reflog`. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
